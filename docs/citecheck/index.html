citecheck · Word add-in for courts

Check every case reference in a draft, inside Word, without the draft leaving the device

citecheck reads the open draft, finds the references to court decisions and compares them with the public OpenCaseLaw cite list: does the decision exist, does it have the cited Erwägung, do page and date match. It is open source (MIT), runs entirely in the Word task pane, and sends nothing.

What it checks

  • Exists. BGE/ATF/DTF, file numbers of the Bundesgericht (all spellings: 4A_747/2012, 4A 747/2012, 4C.230/2006), Bundesverwaltungsgericht, Bundesstrafgericht and cantonal courts, against 1,081,116 decisions, BGE from volume 1.
  • Erwägung. Whether the decision has the cited E. / consid.; if not, which ones it has. Known for about four fifths of the decisions, otherwise marked "cannot be checked".
  • Page and date. For a BGE, whether the cited page lies within the decision; for a file number, whether the written date is the decision's.
  • Typing errors. A near label is offered when it carries the written date or the cited Erwägung, for instance 4A_747/2012 for "4A_747/2013 vom 5. April 2013", or BGE 140 III 115 for "BGE 140 III 120" (p. 120 lies within it).

What it does not do

  • It does not judge whether a decision supports what the draft says.
  • "Not in the list" is not "does not exist": unpublished and very recent decisions are missing. The pane states what the list holds for that court.
  • It never changes the text. It can select a reference and, on request, attach a Word comment.

The pane after a check: a summary, the draft's margin with one mark per reference, and the findings. German, French, Italian and English.

Install in Word

One file, uploaded once in Word. No installer, no administrator rights, no command line. The file (5 KB) contains only the address of the add-in.

Download the add-in file

  1. Open Word. On the Insert tab click Add-ins (in some versions Get Add-ins).
  2. In the Office Add-ins window choose My Add-ins, then Upload My Add-in at the top right.
  3. Pick the downloaded file citecheck-manifest.xml and click Upload.
  4. The pane opens on the right. From then on the button Zitate prüfen sits on the Review tab.

No "Upload My Add-in"? Then your organisation has switched off self-installed add-ins. Your IT can add the same file for chosen users in the Microsoft 365 admin centre (Integrated apps, Upload custom app), or host the add-in on the intranet: deployment guide.

  1. Open the document in Word at office.com. Insert, Add-ins, More Add-ins.
  2. My Add-ins, Upload My Add-in, pick the downloaded file.
  3. The pane opens on the right.
  1. Quit Word.
  2. In the Finder: Go, Go to Folder…, paste ~/Library/Containers/com.microsoft.Word/Data/Documents/wef. If the folder wef does not exist, create it inside Documents.
  3. Move the downloaded file into that folder.
  4. Start Word. Home, Add-ins, under "Developer Add-ins" choose citecheck.

Using it

  1. Open the draft and press Entwurf prüfen. The first time, the add-in loads the cite list (17 MB); afterwards only when the list has changed. Every check first asks whether a newer list exists.
  2. Every reference gets a line: found, differs, not in the list, not checked. Clicking it shows the reason; Im Entwurf zeigen selects the place in the document; Entscheid öffnen opens the decision on opencaselaw.ch, at the cited Erwägung.
  3. Without Word: open the pane in a browser and drop the .docx on it. It is read in the page, not uploaded.

Where the data goes

Three places are involved. The draft stays in the first.

stays on the device public, identical for everyone

The add-in's host

A web server with static files: the add-in's page and the cite list. Today jonashertner.github.io; a court can host the same folder on its intranet.

  • the add-in's page, script and style
  • the cite list: court, date, number and Erwägung numbers of every decision, no text
  • sees only that the pane was opened and the list fetched, as any web server does
public files only nothing about the draft

Your computer, inside Word

The add-in runs in the task pane. Here it reads the draft, finds the references and compares them with the list held in memory.

  • the draft
  • the references found in it
  • the results and any comments
  • a copy of the cite list, kept for the next check
office.js only nothing about the draft

Microsoft

Word loads office.js from appsforoffice.microsoft.com. Every Word add-in must; it is a script, not document data.

  • sees that an add-in was opened, nothing else

Links are the one exception, and only when you click. "Entscheid öffnen" opens that one decision's page on opencaselaw.ch in your browser, like any link in a document. opencaselaw.ch then sees that this page was opened, not the draft and not the other references.

What enforces this, not just promises it.

The add-in's page carries a Content-Security-Policy that allows connections to its own host only. The browser inside Word refuses every other connection, from our code and from Microsoft's script alike. No inline script, no eval, no form posts.

The code has one place that talks to the network, two requests, both to the list next to the page. A test in the repository fails if that policy is loosened, if a second network call appears, or if the Word code does anything but read, select and comment.

You can check it yourself: open the pane with the browser's developer tools and watch the network tab during a check. Nothing is requested. The full description: SECURITY.md.

For a court's IT

The add-in is a folder of static files and one manifest; nothing runs on a server. Copy the folder to an intranet server, mirror the cite list next to it (or build it from the public verification pack), generate the manifest for that address, and roll it out through the Microsoft 365 admin centre or a trusted catalog. Then the workstation contacts no one outside the court but Microsoft's script host. With --read-only the manifest asks Word for read access only. Steps and the nginx lines: deployment guide.

Test version, feedback

citecheck is a test version. For a wrong or missing finding, send the reference as written in the draft and the message the pane shows, as an issue on GitHub or by e-mail. The cite list is rebuilt from the OpenCaseLaw corpus; a decision that is missing from it is usually missing from the corpus, and the coverage page says which courts and years are covered.
