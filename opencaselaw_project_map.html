    §01 Mission & scope

    Every published Swiss decision, verifiable and free.

    The mission is completeness: a full dataset of all published Swiss court decisions plus the laws, preparatory materials, and scholarship needed to interpret them. Deduplication must never remove a legitimate distinct decision.

    Complete

    Federal courts (1875 to present), all 26 cantons, federal regulators, the Military Court of Cassation, and ~2,800 ECHR decisions concerning Switzerland.

    Verifiable

    Every citation and quotation the API emits is sourced verbatim from the corpus, never constructed. An anti-hallucination contract (R1 to R3) is enforced at the tool surface.

    Open

    CC0 data mirrored to HuggingFace, MIT code, a public dashboard, a REST API, and MCP connectors for Claude and ChatGPT.

    §09 The zero-downtime swap

    os.replace(), not restart.

    Step 2 writes decisions.db.tmp then atomically os.replace() over the live path. The 8 workers keep serving from the old inode until their next SQLite connection, so there is no restart and no downtime.

    • immutable=1 tells SQLite the file never changes: no locks, no WAL check
    • DELETE journal build_fts5 switches WAL→DELETE before the swap
    • Workers cycle new connections pick up the new inode automatically

    Field lesson: 2026-07-08

    After a swap, pooled worker connections pin the old (now-unlinked) inode. At 93% disk this starved the aux tier and two builders hit "database or disk is full". Fix shipped: publish.py now rolls the workers after the swap (zero downtime, /health-gated) to release the old inode before the aux tier writes. Manual recovery reclaimed 34 → 164 GB the same way.
    Serving continues on the old inode even mid-swap, which is exactly why availability never drops during the ~6 to 13h rebuild.

    §11 The anti-hallucination contract

    Never construct. Only quote.

    These rules are in the MCP server's own system prompt and are enforced across every tool that returns a citation or a quotation. They exist because practitioners may put this output in front of a court.

    R1 · Citations

    Never build a citation string. Every BGE / BGer / cantonal / EGMR reference is copied verbatim from a citation_string_de/fr/it field or from the cite tool. No source, no cite: describe in prose.

    R2 · Quotations

    Direct quotes come verbatim only from get_erwaegung, get_regeste, get_law, get_commentary, or get_article_purpose. Nothing paraphrased into quotation marks.

    R3 · Grounding

    Any new tool surface must reuse cite() and the verbatim getters rather than assembling references, and is validated for R1 to R3 compliance before shipping, not after.
    §12 Critical invariants · do not break

    The rules the system is built on.

    • 1 · immutable=1 everywhere on the read side, or the swap breaks
    • 2 · Atomic swap decisions.db.tmp → os.replace(), never cp / in-place
    • 3 · FTS5 sanitisation all input through _sanitize_fts5 (quotes OR/AND/NOT/NEAR, strips Art. dot, empty phrases)
    • 4 · Citation contract R1 to R3 respected on every new surface
    • 5 · Pipeline gate publish.py / schema / scraper edits need explicit approval + test on a copy
    • 6 · Scraper egress NE / JU require the reverse-SOCKS tunnel
    • 7 · Health monitoring silent-success detection is ground truth, never silenced
    • 8 · Tests stay offline make test uses fixtures, no live network (~40 to 50s)
    Both-dates requirement: every row needs a decision_date and a publication_date. Dedup keeps the richest-text copy and must never drop a distinct decision.

    §15 Freshness between builds

    Newest decisions, before tomorrow's rebuild.

    Quick-publish

    The BGer poller detects new decisions during the day and quick-publishes them into decisions.db via a mini atomic swap, so "Neueste Bundesgerichtsentscheide" reflects bger.ch fast, without waiting for the nightly.

    RSS feeds

    Step 5b writes 7 feeds (global + bger/bvger/bge + de/fr/it). Reads substr(full_text,1,300), not the full blob: 146x less I/O after a July timeout.

    Delta & alerts

    Step 7 publishes a daily delta. A 15-minute alert dispatcher watches worker health, output freshness, and (new) TLS cert expiry, posting to ntfy.
    Freshness snapshot_date is a content-change signal, not the last scrape time.
